# 测试矩阵

本文档说明 Sisp 当前自动化测试覆盖范围、运行方式和真实磁盘验证边界。

## 1. 运行方式

全量测试：

```powershell
py -m pytest
```

查看完整统计（覆盖 `pytest.ini` 中的 `-q`）：

```powershell
py -m pytest -o addopts="" --tb=short
```

带覆盖率：

```powershell
py -m pytest -o addopts="" --cov=app --cov-report=term-missing
```

代码检查：

```powershell
py -m ruff check app tests
```

默认安全测试入口（pytest + 无效输入报告）：

```powershell
py .\tests\run_all.py
```

CI 配置见 `.github/workflows/ci.yml`，在 Windows 上执行：

- `ruff check app tests`
- `pytest --cov=app --cov-fail-under=70`
- `PyInstaller --clean --noconfirm Sisp.spec`
- `PyInstaller --clean --noconfirm SispGUI.spec`（独立 GUI 构建 job）

## 3. 真实磁盘验证边界

默认测试**不会**：

- 执行 `Clear-Disk`
- 执行 `Initialize-Disk`
- 执行 `New-Partition`
- 执行 `Format-Volume`
- 写入 Ghost 镜像
- 修改真实硬盘分区

需要真实磁盘验证时，请在测试机/虚拟机中手动执行，并至少覆盖：

1. `--version`
2. `--check-config`
3. `--list-disks`
4. `--dry-run`
5. 单盘完整流程
6. 两盘及以上 worker 流程
7. 失败注入（错误镜像路径、错误 Ghost 路径、错误 bcdboot 路径）
8. 系统盘/启动盘保护
9. 盘符不足、盘符被占用、残留幽灵盘符场景
10. 目标盘缺少 `UniqueId` / `SerialNumber` 时拒绝写盘
11. GHO/工具/源目录/配置/日志目录位于目标盘时拒绝执行
12. Ghost/拷贝/bcdboot 前盘符归属变化时中止
13. worker 结果超时/缺失场景
14. GUI：`python -m app.gui` 启动并完成提权
15. GUI：扫描硬盘 → 生成计划 → 计划确认页阻断项门禁
16. GUI：dry-run 跑到结果页，日志与监控表实时刷新
17. GUI：单盘完整流程
18. GUI：多盘错峰执行、取消中状态和结果汇总
19. GUI：关闭窗口时任务仍在执行的协作取消与自动退出
20. GUI：`SispGUI.exe` 双击触发 UAC 并从发布目录正常启动

### 3.1 真机验收结果（2026-10-25，VHDX 沙盒）

环境：Windows 11 Pro for Workstations 10.0.26300，两块一次性 VHDX 挂载为磁盘 2/3（6 GiB，`File Backed Virtual`），真实磁盘 0/1 全程受保护。GUI 由提权 UIA 助手驱动，验收前后真实磁盘基线完全一致。

| 项 | 场景 | 结果 | 说明 |
| --- | --- | --- | --- |
| 14 | GUI 启动并提权 | 通过 | `dist\SispGUI\SispGUI.exe`（清单 `uac_admin`）启动，窗口标题/五页正常；启动即写日志 |
| 15 | 扫描硬盘 → 生成计划 → 门禁 | 通过 | 4 块盘，真实盘 0/1 显示“受保护”（配置排除盘、启动盘、系统盘）；计划页显示型号、容量、UniqueId、4 个盘符、7 个步骤与破坏性警告；确认框默认不勾选、按钮禁用 |
| 16 | dry-run → 结果页、日志与监控刷新 | 通过 | 监控 `0/7 → 2/7 → 3/7 → 4/7`，dry-run 成功、错误码 0；结果页显示日志文件路径，选中行后“打开选中日志”可用 |
| 17 | 单盘完整流程 | 部分通过（1–4 通过，5 失败） | 步骤 1–4 真实写盘通过；步骤 5 因 Ghost 占位程序返回 1 而失败（错误码 4）；磁盘 2 为 GPT + 4 个分区，盘符与计划一致 |
| 18 | 多盘错峰执行与取消 | 通过 | 等待期取消磁盘 3 → “已取消 0/7”，磁盘 3 仍为 `RAW`；运行中取消磁盘 2 → “取消中 / 当前步骤完成后停止”，停在 3/7 变“已取消”；结果页错误码 13、提示“用户取消/操作已取消” |
| 19 | 关闭窗口协作退出 | 通过 | 运行中 Alt+F4 → “任务仍在执行”确认框选 Yes → 显示“正在取消：当前步骤完成后将自动退出” → 当前步骤结束后进程自动退出，未强制结束 |

## 5. 新增测试约定

- 测试文件命名：`test_*.py`
- 测试必须可在无管理员权限、无真实硬盘的 CI 环境中运行。
- 涉及真实 PowerShell 的测试通过注入 runner 或 monkeypatch `subprocess` 完成。
- GUI 测试使用 `QT_QPA_PLATFORM=offscreen`，不启动真实事件循环；未安装 PySide6 时通过 `pytest.importorskip` 跳过。
- 新增主流程步骤时，同步更新：
  - `tests/test_minimal_main_flow.py` 的成功/失败路径
  - `tests/test_observability.py` 的日志/结果断言
  - 本文档的覆盖矩阵
