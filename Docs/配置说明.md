# 配置说明

Sisp2 只有**一处配置来源**：界面「设置」页，落盘为 `settings.json`。

> 旧版本的「业务 JSON 配置文件」（`json/win11.json`、`json/win11.example.json`、
> `-j/--config`、`SISP_CONFIG`）已整条移除。它曾经和设置页重复表达同一批参数，
> 优先级还取决于启动时有没有显式传 `-j`——实测出现过「界面里看着 60 GB、后端
> 按 30 GB 拒绝」这种排查起来很费劲的分歧。现在每个参数只有一处来源。

装机时需要的东西全在设置页：

| 界面位置 | 对应设置项 | 说明 |
| --- | --- | --- |
| 设置 · 安装默认值 | `sysDefaultGb` / `efiDefaultMb` / `dataDefaultGb` | 向导第 2 步的初值，可在那一步按盘修改 |
| 设置 · 系统文件 | `sysImageA` / `sysImageB`（各带 `sysImageALabel` / `sysImageBLabel`） | 两个具名系统槽位，各存一个 GHO；向导第 3 步每块盘二选一 |
| 设置 · 外部程序 | `extGhost` / `extBcdboot` | 外部执行器路径；留空用 PATH 与 `System32` 里的同名 exe，**改完需重启应用** |
| 设置 · 安全与提醒 | `protectSystemDisk` / `releaseEfiLetter` / `logRetentionDays` | 写盘闸门、EFI 盘符收尾、日志清理 |
| 设置 · 日志与诊断 | `logDir` / `logLevel` | 命令日志目录与级别；空目录 = 用户目录下的 Sisp 日志目录，**改完需重启应用** |

数据分区的文件系统**固定为 NTFS**，不可配置（`exFAT` 已从产品里去掉了：
它对装机盘没有收益，却让格式化参数多出一处必须和设置页同步的分叉点）。

## GUI 设置

默认 `%APPDATA%\Sisp\settings.json`；若没有 `APPDATA`，用 `~/.config/Sisp/settings.json`。启动参数 `--settings` 可指定文件。保存格式为 `{"version":1,"settings":{...}}`。读取时坏字段逐项忽略并记录 warning；更新 patch 是整体校验，任一字段非法则不保存；未知字段拒绝。

| 字段 | 默认值 | 校验/已确认行为 |
|---|---:|---|
| `theme` | `light` | `light` / `dark` / `system`；读取后与设置页修改时立即切换 `data-theme` |
| `density` | `comfortable` | `compact` / `comfortable`；切换 `data-density`，紧凑模式收紧卡片内边距、表格行距与字号 |
| `rememberWindow` | `true` | 布尔值；关窗时把窗口位置/大小写入设置文件同目录的 `window.json`，关闭该开关则不保存也不恢复 |
| `protectSystemDisk` | `true` | 布尔值；控制系统盘/启动盘/含系统盘符的盘是否不可选，执行层闸门复用同一判定 |
| `releaseEfiLetter` | `true` | 布尔值；任务收尾是否释放 EFI（ESP）分区的临时盘符。关掉后临时盘符会一直留在盘上（方便手动查看引导文件），但会占用一个盘符；下次 `clean` 前不会被系统自动摘掉 |
| `startView` | `main` | `main` / `install` / `settings`；启动时先打开哪个视图 |
| `autoRefresh` | `true` | 布尔值；打开窗口时自动扫描一次硬盘 |
| `sysDefaultGb` | `120` | 整数 60–2000；系统分区默认大小（向导第 2 步初值，可在向导里逐盘改） |
| `efiDefaultMb` | `100` | 整数 64–1024；EFI（ESP）分区大小；向导第 2 步只显示不可改 |
| `dataDefaultGb` | `auto` | `auto` 或整数 20–100000；数据分区默认大小，`auto` = 剩余空间全给它 |
| `extGhost` | 空字符串 | 路径型字段；Ghost 可执行文件（`ghost64.exe` / `ghost32.exe`），空值回退 PATH 与 System32 探测。**改完需重启应用**（执行器在进程启动时装配）。diskpart 固定用系统自带的，不提供设置项 |
| `extBcdboot` | 空字符串 | 路径型字段；写引导用的 `bcdboot.exe`，空值回退 PATH 与 System32 探测；“修复引导”也用它。**改完需重启应用** |
| `sysImageA` / `sysImageB` | 空字符串 | 文件；两个并列的**系统版本槽位**（预检与执行都用它），必须是 `.GHO`/`.GHS` 且文件头是 Ghost 签名；填了就必须存在。至少一个可用才允许开始，坏掉的那个只影响选它的盘 |
| `sysImageALabel` / `sysImageBLabel` | `Windows 10` / `Windows 11` | 纯文本（≤32 字），向导第 3 步按钮上的名字；留空回退「系统 A」/「系统 B」；两个槽位都填了镜像时名字不能相同 |
| `logRetentionDays` | `30` | 整数 1–3650；进程启动时清理 `logDir` 下超过该天数的 `disk-runner-*.log` 与 `app.log.*`（`logDir` 为空时日志不落盘、也不清理） |
| `logDir` | 空字符串 | 真实执行器命令日志目录；桌面进程还会在其中写 `app.log`（2 MB × 3 轮转） |
| `logLevel` | `info` | `debug` / `info` / `warn` / `error`；设置 `app` logger 级别，桌面进程同时落盘到 `logDir/app.log`；改动在下次启动生效 |

以上开关（`protectSystemDisk`、`releaseEfiLetter`）、外部工具与系统文件路径一旦填写就参与运行：预检会多出「外部工具可用性检查」「设置路径有效性检查」两项，填错路径直接阻断。

> **安全与提醒只保留三项**（`protectSystemDisk` / `releaseEfiLetter` / `logRetentionDays`）。
> 旧版本的 `dryRunByDefault`、`blockUnverified`、`excludedDiskNames` 已同功能一起移除：
> 演练模式现在只由命令行 `--dry-run` 决定；没有 `UniqueId`/`SerialNumber` 的盘不再被置灰，
> 但执行前的写盘闸门仍会重扫一次并按“盘号 + 容量 + 型号”复核（有标识时比对标识）；
> 硬盘型号黑名单整条功能取消，不再有任何地方读取它。旧 `settings.json` 里残留的这三个键
> 读取时会被忽略，下次保存时自动消失。同样被移除的还有 `language`：界面固定简体中文，
> 页面 `lang` 写死 `zh-CN`，该键从来没有读取方；同为旧键的 `imageDefaultIndex`
> （GHO 分区块序号，Ghost 命令固定用第 1 块）、`typeToConfirm` 与 `confirmBeforeStart`
> （输入盘号、二次确认弹窗：授权只剩下第 4 步那一次勾选）也都已移除，留在 `settings.json` 里只会被忽略。

其余字段均已接入运行时。

### 导出 / 导入

设置页顶部的「导出…/导入…」用于把一台机器上的设置带到另一台：

- 导出：桌面窗口会弹原生保存框；浏览器模式（`--serve`）没有保存框，直接落到
  `%APPDATA%\Sisp\sisp2-settings-<时间戳>.json`，返回值里带路径。
- 导入：读 `{"version":1,"settings":{…}}` 封套或裸设置对象都行；**整体校验**，
  任一字段非法就全部不写，错误里带 `field`。
- 对应接口：`POST /api/settings/export`（可选 `path`）、
  `POST /api/settings/import`（`path` 或 `content`）。

生效时机（与设置页每行的提示一致）：

| 时机 | 设置项 | 为什么 |
| --- | --- | --- |
| 立即生效 | `theme`、`density`、`protectSystemDisk` | 界面外观与交互开关；`protectSystemDisk` 由 `WorkflowController.apply_settings()` 热应用，写盘闸门与扫描保护原因同步 |
| 下次启动生效 | `rememberWindow`、`autoRefresh`、`startView` | 窗口位置/首次扫描/起始视图都在窗口初始化时读 |
| 下次生成计划生效 | `sysDefaultGb`、`efiDefaultMb`、`dataDefaultGb` | 每次 `prepare()` / 预检现读 |
| 下次任务生效 | `sysImageA`、`sysImageB` 及两个标签、`releaseEfiLetter` | 生成计划与收尾时取用 |
| **重启后生效** | `extGhost`、`extBcdboot`、`logDir`、`logLevel` | 执行器工具路径在进程启动时装配进 `WindowsDiskRunner`，日志器在启动时 `configure_logging`（实测：改完 `extGhost` 不重启，计划里仍会报“未找到 Ghost 可执行文件”） |
| 启动时执行 | `logRetentionDays` | 随日志器初始化一起清理过期日志 |

`sysDefaultGb + dataDefaultGb` 若两者为数字且总和不大于 60 会被拒绝。路径探测只报告存在状态或系统内置命令，不会验证业务兼容性；预检的单项通过也不代表镜像/引导真的可用。
