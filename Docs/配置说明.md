# 配置说明

Sisp2 只有**一处配置来源**：界面「设置」页，落盘为 `settings.json`。

> 旧版本的「业务 JSON 配置文件」（`json/win11.json`、`json/win11.example.json`、
> `-j/--config`、`SISP_CONFIG`）已整条移除。它曾经和设置页重复表达同一批参数，
> 优先级还取决于启动时有没有显式传 `-j`——实测出现过「界面里看着 60 GB、后端
> 按 30 GB 拒绝」这种排查起来很费劲的分歧。现在每个参数只有一处来源。

装机时需要的东西全在设置页：

| 界面位置 | 对应设置项 | 说明 |
| --- | --- | --- |
| 设置 · 安装默认值 | `sysDefaultGb` / `efiDefaultMb` / `dataDefaultGb` | 向导第 2 步的初值，可在那一步按盘修改 |
| 设置 · 安装默认值 | `imageDefaultIndex` | 默认取 GHO 的第几个分区块，0 = 第一个 |
| 设置 · 系统文件 | `sysIsoDir` / `sysWim` | 向导第 3 步的列目录，与默认镜像 |
| 设置 · 安全与提醒 | `excludedDiskNames` | 禁止操作的硬盘型号 |
| 设置 · 安全与提醒 | `protectSystemDisk` / `blockUnverified` / `typeToConfirm` | 写盘闸门 |

数据分区的文件系统**固定为 NTFS**，不可配置（`exFAT` 已从产品里去掉了：
它对装机盘没有收益，却让格式化参数多出一处必须和设置页同步的分叉点）。

## GUI 设置

默认 `%APPDATA%\Sisp\settings.json`；若没有 `APPDATA`，用 `~/.config/Sisp/settings.json`。启动参数 `--settings` 可指定文件。保存格式为 `{"version":1,"settings":{...}}`。读取时坏字段逐项忽略并记录 warning；更新 patch 是整体校验，任一字段非法则不保存；未知字段拒绝。

| 字段 | 默认值 | 校验/已确认行为 |
|---|---:|---|
| `language` | `zh-CN` | `zh-CN` / `en-US`；界面文案固定为简体中文，但会同步页面 `lang` 属性（影响拼写检查/朗读/字体回退） |
| `theme` | `light` | `light` / `dark` / `system`；读取后与设置页修改时立即切换 `data-theme` |
| `density` | `comfortable` | `compact` / `comfortable`；切换 `data-density`，紧凑模式收紧卡片内边距、表格行距与字号 |
| `rememberWindow` | `true` | 布尔值；关窗时把窗口位置/大小写入设置文件同目录的 `window.json`，关闭该开关则不保存也不恢复 |
| `confirmBeforeStart` | `true` | 布尔值；实际执行模式下，未勾选「我已核对目标磁盘」时提交/确认按钮禁用，并在提交前弹一次确认框 |
| `typeToConfirm` | `true` | 布尔值；真实执行前 `/api/confirm` 必须带匹配的 `confirm_text`（盘号如 `1` 或磁盘型号，忽略大小写与空白），否则 `E_CONFIRM`（`1`、`disk 1`、`硬盘1`、型号等写法都接受）|
| `excludedDiskNames` | `[]` | 字符串数组；一行一个硬盘**型号子串**（不区分大小写），命中即禁止操作该盘：向导置灰、整盘安装被拒、分区与修复引导同样被拒。这是排除名单的唯一来源，且不受任何开关影响 |
| `protectSystemDisk` | `true` | 布尔值；控制系统盘/启动盘/含系统盘符的盘是否不可选，执行层闸门复用同一判定 |
| `blockUnverified` | `true` | 布尔值；控制缺少 `UniqueId`/`SerialNumber` 的盘是否不可选，执行层闸门同样生效 |
| `releaseEfiLetter` | `true` | 布尔值；任务收尾是否释放 EFI（ESP）分区的临时盘符。关掉后临时盘符会一直留在盘上（方便手动查看引导文件），但会占用一个盘符；下次 `clean` 前不会被系统自动摘掉 |
| `startView` | `main` | `main` / `install` / `settings`；启动时先打开哪个视图 |
| `autoRefresh` | `true` | 布尔值；打开窗口时自动扫描一次硬盘 |
| `sysDefaultGb` | `120` | 整数 60–2000；系统分区默认大小（向导第 2 步初值，可在向导里逐盘改） |
| `efiDefaultMb` | `100` | 整数 64–1024；EFI（ESP）分区大小；向导第 2 步只显示不可改 |
| `imageDefaultIndex` | `0` | 整数 0–99；GHO 里的**分区块序号**（一个 GHO 可含多个分区块），`0` = 交给 Ghost 用第一个；向导第 3 步可逐盘覆盖。这是 `image_index` 的唯一来源 |
| `dataDefaultGb` | `auto` | `auto` 或整数 20–100000；数据分区默认大小，`auto` = 剩余空间全给它 |
| `extEnabled` | `true` | 布尔值；关掉后一律用系统自带命令，忽略下面填的外部工具路径 |
| `extConfirm` | `false` | 布尔值；调用外部程序前是否先弹确认 |
| `extDiskpart`、`extGhost` | 空字符串 | 路径型字段；作为真实执行器的程序路径（`ghost64.exe` / `ghost32.exe`），空值回退 exe 目录 `sw\` 与 PATH / System32 探测 |
| `extVentoy`、`ext7z` | 空字符串 | 路径型字段；参与运行前检查：一旦填写就必须存在，否则预检不通过（不驱动执行流程） |
| `sysTemp` | 空字符串 | 目录；作为 ghost/diskpart 子进程的 `TMP`/`TEMP`，不存在会自动创建；与 `logDir` 相同会被拒绝 |
| `sysBoot` | 空字符串 | 目录；设置后作为 `bcdboot` 的源目录（镜像里没有 `Windows\Boot` 时的兜底） |
| `sysWim` | 空字符串 | 文件；**镜像的唯一来源**（预检与执行都用它），必须是 `.GHO`/`.GHS` 且文件头是 Ghost 签名；填了就必须存在，否则预检阻断 |
| `sysIsoDir` | 空字符串 | 目录；安装向导第 3 步从这里列镜像；同时参与运行前检查 |
| `dryRunByDefault` | `false` | 布尔值；GUI 启动时与 `--dry-run` 取逻辑或，影响会话模式 |
| `logRetentionDays` | `30` | 整数 1–3650；启动时清理 `logDir` 下超过该天数的 `disk-runner-*.log`、`boot-disk*.log` 与 `app.log.*` |
| `logDir` | 空字符串 | 真实执行器命令日志目录；桌面进程还会在其中写 `app.log`（2 MB × 3 轮转） |
| `logLevel` | `info` | `debug` / `info` / `warn` / `error`；设置 `app` logger 级别，桌面进程同时落盘到 `logDir/app.log`；改动在下次启动生效 |

以上开关（`protectSystemDisk`、`blockUnverified`、`excludedDiskNames`）、执行器可选项（`sysTemp`、`sysBoot`）、外部工具与系统文件路径一旦填写就参与运行：预检会多出「外部工具可用性检查」「设置路径有效性检查」两项，填错路径直接阻断。

`language` 只影响页面 `lang` 属性与持久化，未做多语言文案；其余字段均已接入运行时。

### 导出 / 导入

设置页顶部的「导出…/导入…」用于把一台机器上的设置带到另一台：

- 导出：桌面窗口会弹原生保存框；浏览器模式（`--serve`）没有保存框，直接落到
  `%APPDATA%\Sisp\sisp2-settings-<时间戳>.json`，返回值里带路径。
- 导入：读 `{"version":1,"settings":{…}}` 封套或裸设置对象都行；**整体校验**，
  任一字段非法就全部不写，错误里带 `field`。
- 对应接口：`POST /api/settings/export`（可选 `path`）、
  `POST /api/settings/import`（`path` 或 `content`）。

生效时机分三档：界面外观（`theme`、`density`）与安全开关（`protectSystemDisk`、`blockUnverified`、`typeToConfirm`、`excludedDiskNames`）保存后立即生效；`confirmBeforeStart` 是界面交互开关，下一次提交/确认就读新值；日志器相关（`logDir`、`logLevel`）在进程启动时装配，改动下次启动生效（`logRetentionDays` 的清理也发生在启动时）。

`sysDefaultGb + dataDefaultGb` 若两者为数字且总和不大于 60 会被拒绝；`sysTemp` 与 `logDir` 相同也会被拒绝。路径探测只报告存在状态或系统内置命令，不会验证业务兼容性；预检的单项通过也不代表镜像/引导真的可用。
