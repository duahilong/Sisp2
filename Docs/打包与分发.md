# 打包成 exe

把 Sisp2 打包成**单文件、免安装**的 Windows 程序。产物不写注册表、不需要
Python 环境，双击即用。

## 产物

| 文件 | 说明 | 实测体积 |
| --- | --- | --- |
| `dist/Sisp2.exe` | 图形界面（无控制台窗口），双击打开「硬盘工具箱」 | 约 19 MB（2026-11-12/13 四次构建：开发机 Python 3.14.6 + PyInstaller 6.22.2 → 18,912,276 / 18,919,125 B；测试 VM Python 3.15.2 + PyInstaller 6.22.3 → 19,226,750 / 19,228,082 B；1.5.0 发版产物 18,909,693 B。onefile；换解释器/打包器版本在 18–23 MB 之间浮动） |

命令行产物 `Sisp2-CLI.exe` 已随 `app/cli.py` 一起移除；扫盘、装机、分区、修复引导、
镜像文件头校验都在界面里完成。

产物是 onefile：启动时会把自己解到 `%LOCALAPPDATA%\Sisp\run` 下的临时目录再运行（spec 的
`runtime_tmpdir`），所以**首次启动约 1–3 秒**（杀毒软件首次扫描时更久），属正常现象。

## 构建

```powershell
python -m pip install -r requirements-build.txt
python packaging/build.py
```

- `python packaging/build.py --no-clean`：跳过 PyInstaller `--clean`，快一些；
- `python packaging/build.py --clean-only`：只清理 `dist/` 与 `build/pyinstaller/`；
- 图标缺失时会自动调用 `packaging/make_icon.py` 生成 `packaging/sisp2.ico`；
- 版本号只有 `app/version.py` 一个来源，`packaging/version_info.txt` 必须与之
  一致，`tests/test_packaging.py` 会检查。发版时还要在仓库里打一个**注释 tag**
  （`git tag -a v1.2.1 -m "..."`，`git push origin main --tags`）：tag 指向的提交树
  就是那一版的源码 + 文档快照，回到某一版用 `git checkout v1.1.0` 或
  `git archive v1.1.0 -o sisp-1.1.0.zip`（新版同理）；变更记录写在仓库根的 `CHANGELOG.md`。
  `dist/` 不进版本库，exe 附在 GitHub Release，提交说明里记字节数与 MD5。

构建必须**在 Windows 上、用目标 Python 版本**执行（onefile 里带的是当前解释器
的 `python3xx.dll`）。当前构建/验证环境：Python 3.15.2 + PyInstaller 6.22.3（2026-11-12
实测；体积会随依赖版本上下浮动 1–2 MB，以 `dist/` 实际产物为准）。

## 自动构建与滚动 Beta

`.github/workflows/windows-tests.yml` 是完整的 main 分支交付流水线：

1. Python 3.10 / 3.12 并行执行 ruff、`compileall` 和全部非破坏性 pytest；
2. 两个版本都成功后，从 ``app/version.py`` 读取基础版本，与 `GITHUB_RUN_NUMBER` 组成
   `X.Y.Z-beta.N`；Python 3.12 + PyInstaller 在干净的 Windows runner 构建 exe；
3. `python packaging/build.py --version X.Y.Z-beta.N` 在构建期临时把完整版本写入
   ``app/version.py`` 和 Windows 版本资源，结束后恢复基础模板。关于页面通过 `/api/info`
   显示完整版本，exe 的数值版本为 `(X,Y,Z,N)`，字符串 FileVersion/ProductVersion 为
   `X.Y.Z-beta.N`；构建后读取 exe 的 ProductVersion 验证一致；
4. 检查产物非空并生成 `Sisp2-beta.exe.sha256`，同一构建在 Actions Artifacts 保留 7 天；
5. 把 `beta` tag 移到当前提交，创建或更新同名**滚动 Beta Release**，标题为
   `Sisp2 X.Y.Z-beta.N`，用 `--clobber` 替换旧 exe 与校验文件。Release 说明记录完整版本、
   提交、工作流、字节数和 SHA256。首次迁移时，新 beta 附件上传成功后才删除旧 nightly。

任何检查、测试或构建失败都会阻止发布。连续推送通过 workflow concurrency 取消旧运行，
避免后完成的旧构建覆盖新产物；PR 与手动触发不发布。仓库使用自动提供的 `GITHUB_TOKEN`
和 `contents: write`，不需要额外配置个人访问令牌。

`beta` 是滚动预发布通道，不代表完成真实写盘验收。固定下载地址：
`https://github.com/duahilong/Sisp2/releases/download/beta/Sisp2-beta.exe`。
稳定版仍按下方版本号、真实 VM 验证和 `v*` 注释 tag 流程单独发布。

## 运行时的文件位置

打包后 `__file__` 不再指向源码目录，路径统一由 `app/resources.py` 解析：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 界面 `ui/index.html` + `ui/css` + `ui/js` | exe 内部资源 | 只读，随包发布（spec 的 `DATAS` 必须整目录带上，否则 exe 只剩空壳） |
| 设置 `settings.json` | `%APPDATA%\Sisp\` | 与源码运行完全一致，exe 升级不会丢；设置页可导出/导入换机 |
| 窗口位置 `window.json` | `%APPDATA%\Sisp\` | 受 `rememberWindow` 控制 |
| 执行日志、`app.log` | 设置里的 `logDir`（留空时 `%APPDATA%\Sisp\logs`） | 无控制台窗口时，这里是唯一的诊断出口 |
| 解包目录 | `%LOCALAPPDATA%\Sisp\run\_MEIxxxx` | onefile 临时目录（spec 的 `runtime_tmpdir`），退出后自动清理 |

设置不依赖 exe 所在目录：一律写 `%APPDATA%\Sisp\`（无 `APPDATA` 时退回用户目录下的
`.config/Sisp/`），所以装在 `C:\Program Files\` 之类只读目录也能正常保存；需要换位置就用
`--settings <路径>`（旧版本的业务 JSON 配置文件与 `-j` 参数已移除）。

## 提权

**界面进程不提权。** 打包清单是 `asInvoker`（spec 里 `uac_admin=False`），双击 exe
不会弹 UAC；需要管理员权限的写盘由界面用 UAC 拉起的**后端子进程**承担：

```
Sisp2.exe                      (asInvoker, 只有窗口 + WebView2)
  └─ Sisp2.exe --backend --serve --port N --parent-pid <界面 pid>   (runas, 提权)
        加载的是同一个 exe、同一个本机 HTTP 服务
```

为什么不能像以前那样直接把 exe 声明成 `requireAdministrator`：**WebView2 的运行时不支持
跑在高完整性（High IL）进程里**。它必须把 `msedgewebview2.exe` 降到 Medium IL 启动，
而这条降权路径要借 `explorer.exe` 代劳（见 WebView2Feedback #2984 与微软
“Develop secure WebView2 apps”）。一旦降权子进程创建失败，用户看到的就是：

```
msedgewebview2 has stopped working
Error launching CrashSender.exe
```

第二行是崩溃报告器也拉不起来的二次报错，不是根因。另一个死结：提权进程下
`WEBVIEW2_*` 环境变量会被忽略，所以“设个环境变量绕过”在这个场景里行不通。

细节：

- 界面侧判断「有没有管理员」是 `app/gui/elevation.py` 的 `IsUserAnAdmin()`，预检仍会复核；
- 后端由 `app/gui_web/main.py` 的 `spawn_privileged_backend()` 拉起，参数里带
  `--parent-pid`：**父进程一退出后端就自己退**（界面没有权限结束一个提权进程，
  所以清理只能由后端自己完成，界面被强杀也不会留下持管理员令牌的 HTTP 服务）；
- 用户在 UAC 上点“否”时不会白屏退出：退回**进程内**的普通权限服务，界面照常打开，
  真正写盘会被预检拦住（`需要管理员权限：请以管理员身份重新启动`）；
- 桌面模式下 `--elevate` 不再需要（后端天然走 UAC）；`--serve` 仍可用它自提权；
- WebView2 的 user data folder 固定在 `%LOCALAPPDATA%\Sisp\WebView2`（`webview.start(storage_path=...)`），
  不再用 `%TEMP%` 下那份易被清掉/被多份 pywebview 应用共用的目录——crashpad
  起不来时同样会弹 `Error launching CrashSender.exe`；
- 产物验证方法：`[Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes('Sisp2.exe'))`
  里应能搜到 `asInvoker`，搜不到 `requireAdministrator`。

## 运行环境要求（老 Win10 必看）

桌面窗口的渲染内核由 pywebview 选：**「.NET Framework ≥ 4.6.2」且「WebView2 运行时
主版本 ≥ 86」同时满足才用 Chromium**，否则 pywebview 会**静默**退回 MSHTML（IE11）。
界面是 `<script type="module">` + `fetch` 写的，IE11 一行都执行不了 —— 表现出来就是
“窗口打开了、标题栏导航都在、磁盘一片空白、状态一直停在连接中、点什么都没反应”。
后端完全是好的（页面就是这个后端发的），坏的只是渲染内核。

1.2.2 起不再把这个状态丢给用户猜：

- 建窗之前 `app/gui/webengine.py` 按 pywebview **同一套判据**探测内核
  （同为 `HKCU\SOFTWARE\Microsoft\EdgeUpdate\Clients\{GUID}` 与
  `HKLM\SOFTWARE\WOW6432Node\...`，同样只比主版本，不自己加严）；
- 不满足就**弹消息框**写清缺什么、给出 WebView2 下载地址和 `--serve` 的替代方案，
  然后以**退出码 5** 退出，不再打开一个点不动的窗口；
- 窗口进程也写 `%APPDATA%\Sisp\logs\app.log`：内核探测结果、提权后端拉起、
  UAC 被拒、端口占用、服务超时都会留痕（以前这些都只走 stderr，而 exe 是
  `console=False`，等于没有）；
- 前端还有一层兜底 `ui/js/engine-guard.js`（ES5 普通脚本，排在 `main.js` 之前）：
  内核明显跑不了模块、或 10 秒内主模块没置位 `window.__sispBooted`，就在页面顶部
  压一条红条说明原因。

排查顺序（故障机上）：

```powershell
# 1) WebView2 运行时版本（空或主版本 < 86 = 命中）
(Get-ItemProperty 'HKLM:\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}' -EA 0).pv
(Get-ItemProperty 'HKCU:\SOFTWARE\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}' -EA 0).pv
# 2) .NET Framework（< 394802 即 < 4.6.2，装了 WebView2 也没用）
(Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full').Release
# 3) 后端到底活没活（窗口开着时；能返回 JSON 说明后端没问题）
Invoke-RestMethod http://127.0.0.1:8765/api/info
# 4) 有没有 WebView2 子进程（没有 = IE 内核在跑）
(Get-Process msedgewebview2 -EA 0 | Measure-Object).Count
```

修复：装 [WebView2 Evergreen Standalone（x64）](https://go.microsoft.com/fwlink/p/?LinkId=2124703)；
老 Win10（1507/1516）先升级 .NET Framework 4.8。不想装运行时就用
`Sisp2.exe --serve --port 8765` + **Edge/Chrome**（不要用 IE 打开）。

## 运行方式

```powershell
.\Sisp2.exe                       # 桌面窗口（默认；会弹一次 UAC 拉起提权后端）
.\Sisp2.exe --serve --port 8890   # 浏览器模式（真实写盘，确认后才执行）
.\Sisp2.exe --serve --port 8765   # 浏览器模式，自己开浏览器访问 127.0.0.1:8765
.\Sisp2.exe --settings D:\cfg\settings.json   # 指定设置文件
```

没有需要手工维护的配置文件：分区大小、默认镜像、外部工具路径全在界面设置里，
落盘为 `%APPDATA%\Sisp\settings.json`。（旧版本的 `json/win11.json` 已移除。）

## 启动耗时

单文件 exe 每次启动都要把包解到 `%LOCALAPPDATA%\Sisp\run\_MEIxxxxxx`，所以首启比源码运行慢。
计时口径：从进程创建到 `GET /health` 返回 200（`--serve`）。

| 场景 | 观察值 |
| --- | --- |
| 单文件 exe（1.4.1，Python 3.14.6 / PyInstaller 6.x） | 约 2.6 s |
| 单文件 exe（**1.5.0**，会话改成后台热身） | **约 0.5 s** |
| 目录版（曾试验过，现已回退） | 约 0.6 s |

1.5.0 把「预检 + 扫盘」从启动路径里挪到后台线程（`_warm_session()`），
`/health` 一 bind 就能应答，窗口不必等 PowerShell 扫描跑完；界面首屏改成
先画骨架、再并行取数，并去掉了启动时多余的一次全盘扫描
（1.4.1 首屏约 4.7 s，1.5.0 约 1.7 s，见 `CHANGELOG.md` 与
`Docs/历史测试记录.md` 第十五节）。

> 目录版（onedir）曾实现并在本机验证过启动更快，但为了先保证「单文件 exe 稳定可运行」
> 已回退；需要时可按 `Docs/打包与分发.md` 的历史提交重新引入（`54bd719`）。

桌面窗口模式（不带 `--serve`）还要额外付出 pywebview + WebView2 初始化与建窗的时间，
比上表再慢一档。

## 已知限制

- **未签名**：会触发 SmartScreen「未知发布者」，也会被杀软按“打包的 Python
  程序”对待。正式分发建议买代码签名证书并对产物签名。
- **onefile 启动慢**：每次启动都要把整包（dll + pyc + datas，约 19 MB）解到
  `%LOCALAPPDATA%\Sisp\run`（spec 的 `runtime_tmpdir` 固定值），再加载解释器与 FastAPI，杀软还会扫一遍新写出的文件。
  要快就 `--onedir`（不解包），或把 exe 交给安装器分发；改 `runtime_tmpdir` 到其它 SSD 路径
  能省一点，但省不掉解包本身。具体耗时见上面「启动耗时」一节。
- **个别受策略管理的目录里，单文件 exe 起不来**：现象是弹窗
  `Could not create temporary directory!`（PyInstaller bootloader 无法创建解包目录，
  `CreateDirectoryW` 连试 5 次失败）。它跟两个东西有关，**与产物本身无关**：
  - 解包目标：现在固定为 `%LOCALAPPDATA%\Sisp\run`（spec 的 `runtime_tmpdir`），
    不再用 `%TEMP%`——`%TEMP%` 被组策略、沙箱、杀软或清理工具管着的机器上这里会失败；
  - 启动位置：某些沙箱/EDR 会限制“从特定目录启动的进程”只能写那个目录内部，
    此时把**同一个 exe** 换到普通目录（例如 `D:\sisp2-release\`）双击就能正常运行。

  排查时先看 `%LOCALAPPDATA%\Sisp\run` 能不能建目录，再换一个启动位置试。
- **`app.log` 是唯一日志出口**：`--windowed` 没有控制台，`print` 的内容会进
  `os.devnull`，排查问题请看设置里 `logDir` 下的 `app.log`。
- **不能跨平台**：产物含 Windows 专属的 WebView2 / WinForms 组件。
