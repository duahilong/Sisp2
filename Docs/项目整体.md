# 项目名称 ：Sisp - System Installation Script Project

## 整体介绍
结合编写的工具、脚本和外部软件，来实现对多个或者单个硬盘的系统安装。通过对硬盘的初始化、格式化、分区、克隆操作系统等一系列操作，实现对硬盘的完整制作。


## 项目技术架构
项目整体使用 Python 编写，结合外部软件和 Windows PowerShell 命令，实现完整流程。
- 工具：ghost64.exe、bcdboot.exe 等，更详细的说明 [引用外部软件信息.md](引用外部软件信息.md)
- 脚本：硬盘分区相关操作通过 Windows PowerShell 命令执行。
- 模块：通过 Python 编写模块，来实现各个功能。

## 运行前置条件
- 项目运行环境为 Windows。
- 源码运行需要 Python 3.12 及以上。
- 项目依赖 PowerShell 执行磁盘相关命令。
- 程序需以管理员权限运行。
- 若未以管理员权限运行，程序应在流程开始前终止，并提示用户重新以管理员身份启动。

## Python 项目依赖
- 当前项目使用 `requirements.txt` 管理运行依赖，`requirements-dev.txt` 管理开发/测试依赖。
- 当前已声明运行依赖：`wcwidth>=0.2.13`

## 运行方式与 JSON 配置文件
- 主程序默认读取 `json/win11.json` 配置文件。
- 可直接执行默认方式运行：`py .\app\main.py`
- 若需要指定其他 JSON 配置文件，可通过 `-j` 参数传入路径。
- 示例：`py .\app\main.py -j .\json\win11.json`
- 示例：`py .\app\main.py -j D:\Code-Project\Sisp2\json\win11.json`
- 多硬盘执行时，主程序会为每个被选择的硬盘启动独立 Python worker 窗口。
- worker 模式主要由主程序自动启动，也可用于单盘调试：`py .\app\main.py --worker-disk 2 -j .\json\win11.json`。
- 只读诊断命令：`--list-disks`、`--check-config`、`--dry-run`、`--version`。
- 文件日志默认写入 `%LOCALAPPDATA%\Sisp\logs`，可通过 `--log-dir` 指定。

```

硬盘分区和格式化
验证分区和格式化结果
```

## 磁盘操作安全规则

- 默认禁止操作系统盘、启动盘和配置中排除的硬盘。
- 当前策略是用户选择可选硬盘后直接进入后续模块。
- 破坏性操作前必须显示目标硬盘编号、型号、容量、盘符等关键信息。
- 目标硬盘必须至少具备 `UniqueId` 或 `SerialNumber` 之一；身份信息不足时拒绝写盘。
- 初始化和分区步骤会在 PowerShell 层再次校验目标硬盘身份，并紧邻 `Clear-Disk` / `New-Partition` 执行断言。
- 当前运行中已占用的盘符（包括选中硬盘自身的旧盘符）本轮不得复用；每次创建分区前检查盘符空闲，Ghost/拷贝/bcdboot 前检查盘符归属。
- GHO、外部工具、源目录、配置、日志/结果目录、程序目录和 Python 解释器不得位于任何目标硬盘上；资源检查在清盘前完成。
- 任一步失败后必须中止后续破坏性操作，并输出失败原因。

## 多硬盘 worker 执行说明

- 用户只选择一个硬盘时，主程序在当前窗口直接执行后续流程，结束前等待用户按 Enter 退出。
- 用户选择多个硬盘时，主程序不在当前窗口直接执行磁盘操作，而是为每个硬盘启动一个独立 Python worker 窗口。
- 每个 worker 窗口只处理一个硬盘，按完整流程执行当前已实现阶段。
- 每个 worker 会重新执行运行前检查、重新读取配置、重新扫描硬盘并重新应用磁盘保护。
- 主程序自动启动 worker 时，会传入目标硬盘的 `UniqueId`、`SerialNumber`、型号和容量；若目标盘缺少强身份字段，主程序会在启动 worker 前拒绝执行，worker 重新扫描后还会进行身份二次确认。
- 主程序启动多个 worker 时，默认在相邻 worker 之间等待 6 秒（可通过 `--worker-interval` 调整），降低多个 USB 硬盘同时执行初始化和分区时的存储服务抖动。
- worker 之间互不共享执行状态，便于分别查看每个硬盘的执行结果。
- worker 将结果写入 JSON 文件，主窗口等待并输出统一汇总；等待上限可通过 `--worker-result-timeout` 调整。
- worker 窗口执行完成后默认保持打开，方便查看输出和错误信息。

## 图形界面执行说明

- 入口：源码运行 `py -m app.gui`，或使用打包后的 `dist/SispGUI/SispGUI.exe`。
- GUI 复用 `WorkflowController`：`start()` 做运行前检查并扫描硬盘，`prepare()` 生成每块盘的执行计划，`submit()`/`confirm()` 提交任务，`cancel()` 请求协作式取消，`results()` 汇总结果。
- 五页流程：配置检查 → 硬盘选择 → 计划确认 → 执行监控 → 结果汇总。
- 计划确认页必须展示硬盘编号、型号、容量、身份字段、四个盘符、7 个执行步骤和破坏性警告；存在阻断项时禁止确认。
- GUI 使用进程内 `JobManager` 线程，多盘任务按启动间隔和并发上限调度；CLI 多盘仍使用独立 worker 进程。
- 非管理员启动时会请求 UAC 提权；调试时可设置 `SISP_NO_ELEVATE=1` 跳过提权。
- GUI 启动时初始化文件日志（可用 `--log-dir` 覆盖），结果页展示日志路径并支持“打开选中日志”。
- 每次生成新计划都会复位确认框，上一轮（含 dry-run）的勾选不会延续到真实写盘计划。
- 关闭窗口时若任务未结束，界面只请求取消，等待当前步骤完成后自动退出。

## 测试安全说明

- 测试基于 pytest 组织，可直接运行 `py -m pytest`；默认安全测试入口为：`py .\tests\run_all.py`（等价于 pytest 全量运行，并额外生成无效输入场景报告）。
- 当前共 259 个测试，综合覆盖率约 84%；CI 覆盖率门槛为 70%。
- 代码检查：`py -m ruff check app tests`；CI 在 Windows 上执行 ruff、pytest 和 PyInstaller 构建。
- 测试矩阵详见 [测试矩阵.md](测试矩阵.md)，常见问题详见 [故障排查.md](故障排查.md)。
- 默认安全测试使用模拟磁盘数据，不读取或修改本机真实硬盘。
- `tests/test_disk_info_raw.py` 会读取本机真实磁盘信息，仅作为手动诊断工具使用，不包含在默认安全测试入口中（该文件无 `test_` 前缀函数，pytest 不会自动收集）。
- 默认安全测试会覆盖初始化、分区和验证逻辑，但通过 mock 和脚本文本断言完成，不会对真实硬盘执行 `Clear-Disk`、`Initialize-Disk`、`New-Partition` 或 `Format-Volume`。
