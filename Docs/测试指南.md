# 测试与真实写盘验证

本项目会清空目标硬盘。测试分三层，**任何真实写盘都只能在一次性虚拟磁盘或专用测试 VM 上进行**。

> **硬规则（2026-11-06 事故后加入）：`pytest` 里绝不允许真实写盘。**
> `app/safety_guard.py` 会在执行前拦下 `diskpart` / `format` / `bcdboot`、非 `/Get-*` 的
> `ghost64 -clone`，以及含写盘 cmdlet（含 `Mount-DiskImage`）、外部写盘程序调用、`-File` /
> `-EncodedCommand` / `iex` 这类看不到内容的 PowerShell 命令；`WindowsDiskRunner` /
> `BootRepairer` / `WindowsDiskRunner` 默认 `allow_real_disk=False`，`tests/conftest.py` 还会全局设置
> `SISP_BLOCK_REAL_DISK=1`。事故经过与复盘见 `Docs/事故报告-2026-11-06-磁盘被格式化.md`。

前端没有构建步骤，所以检查也分两层：

python tools/ui_check.py                                               # node --check + 引用 + derive.js 行为

  引用必须存在；相对 `import` 必须能解析；把 `derive.js` 复制成 `.mjs` 在 node 里真实跑

  确认页提示合并（`mergePlanNotes`：多盘同一句提示只留一行、盘号去重）。
  `tests/test_ui_assets.py::test_frontend_static_check` 会代调它。
- `tools/ui_smoke.mjs`：CDP 直连 headless Chrome（不依赖 Playwright），依次走主页面、

  `Log.entryAdded`，截图十余张（按分支），并对 `.dsel`/`.tgt`/计划卡片数 `.pcard`
  与分区行数 `.pline`/`#wzNext`/`.set-row` 做计数断言（第 3 步的系统版本按钮**还没纳入断言**，见“已知限制”）；
  第 2 步还会真点一次「➕ 添加数据分区」：要求出现
  1 行 `.szrow.extra`（名字就是“数据分区”、**没有**文件系统下拉）、进度条 4 段、D/E
  平分容量、➕ 隐藏；然后用合成 PointerEvent 分别拖 **D|E** 和 **C|D** 两根分隔条，
  断言 D/E 互换但总量不变、总量不超过盘容量（盘容量**从 `/api/disks` 取真实字节数**，

  计划卡片里出现两个数据分区——这条路径以前只能靠人眼看截图；**截图小于 20 KB 视为空白直接判失败**（曾经因为

## 2. 专用 VM：只读与 dry-run

### 先把代码/产物送到 VM：优先走 Git

大文件（源码树、`dist/Sisp2.exe`）**不要用 MCP 的文件通道搬**：

- `read` 超过 50 KB 会被截断，写回去就是半个文件；
- 写入会把 LF 转成 CRLF，`git apply` 直接失败（退出码 128），而且补丁里的行尾混着两种；
- 实测能用的兜底只有“分片 base64 + VM 端解码”，又慢又容易传错。

所以默认流程：本机 `git push` → VM 上 `git pull` / `git clone` → 在 VM 里跑测试。
只需要跑产物时才把 `dist/Sisp2.exe` 单独拷过去，并核对 SHA256。

推荐在专用 Windows VM 上验证真实 PowerShell 扫描与 GUI：

```powershell
python -m app.gui_web.main --serve --dry-run --port 8765
```

检查项：
- 磁盘列表、系统盘/启动盘保护、盘符分配、缺镜像/容量不足的阻断；
- `GET /health`、`/api/info`、`/api/disks`、`/api/prepare`；
- `--dry-run` 会话下，API 传 `dry_run:false` 仍应保持演练；
- 重复 `submit` 返回 `E_SUBMIT`。

## 3. 一次性 VHDX：真实写盘（推荐）

不碰系统盘和物理盘，测完直接 detach/删除。需要管理员权限。

### 3.1 创建并挂载测试盘

```powershell
New-Item -ItemType Directory -Force D:\sisp-test | Out-Null
@'
create vdisk file="D:\sisp-test\sisp-test.vhdx" maximum=102400 type=expandable
select vdisk file="D:\sisp-test\sisp-test.vhdx"
attach vdisk
exit
'@ | Set-Content $env:TEMP\vhd.txt -Encoding ASCII
diskpart /s $env:TEMP\vhd.txt
Get-Disk   # 找到新出现的 "Msft Virtual Disk"（RAW、File Backed Virtual）
# type=expandable 只占实际写入的空间：100 GB 声明容量不意味着立刻吃掉 100 GB 磁盘
```

### 3.2 准备一个合法测试 GHO

真实执行器只认 Ghost 分区块镜像：后缀 `.GHO` / `.GHS`，文件头是 `FE EF`。没有现成
GHO 时，用 Ghost 自己打一个（这也是 VM 上最好用的办法，不用传大文件）：

```powershell
# 源盘先分好区，把要还原的内容放进 2 号分区（NTFS，已分配盘符），然后：
ghost64.exe -clone,mode=pdump,src=3:2,dst=D:\sisp-test\test.gho -sure -batch -z9
#            ↑ Ghost 的 1 基磁盘号:分区号（Windows 的 disk 2 → Ghost 的 3）
```

然后按 3.1 的方式建一次性 VHDX 当**目标盘**（容量下限见 3.3），并把「设置 → 系统文件」里
系统 A / 系统 B 的某个槽位指向这个 `.gho`（向导第 3 步再按盘二选一）。
Ghost 还原不会扩容：镜像里的分区多大，还原出来就是多大，所以系统分区大小最好与源分区一致。

> 合成出来的 GHO 只用于验证命令链路，不是可启动的 Windows 镜像；真正验证装机可启动性
> 需要官方镜像封装出来的 GHO。

### 3.3 配置与执行

配置只有一处来源：界面「设置」。真实写盘前先在那里填好：

| 设置项 | 例子 | 说明 |
| --- | --- | --- |
| `sysImageA`（或 `sysImageB`） | `D:\sisp-test\test.gho` | 「设置 → 系统文件 → 系统 A/B 镜像」；向导第 3 步按盘二选一 |
| `sysImageALabel` / `sysImageBLabel` | `Win10 精简版` / `Win11 全量` | 第 3 步按钮上的名字，≤32 字 |
| `sysDefaultGb` / `dataDefaultGb` / `efiDefaultMb` | `120` / `auto` / `100` | 第 2 步的初值，可在向导里逐盘改 |
| `extGhost` | `D:\sisp-test\ghost64.exe` | 找不到 Ghost 时计划阶段直接阻断。**改完必须重启应用**（外部程序路径在进程启动时装配） |
| `extBcdboot` | 留空即可（用 `System32\bcdboot.exe`） | 只有当机器上另有一份 `bcdboot.exe` 想指定时才填；填了就必须存在，否则预检不通过 |
| `logDir` | `D:\sisp-test\gui-logs` | 命令日志目录；子进程临时文件统一走系统 `%TEMP%` |

> **测试盘容量下限**：C ≥ 60 GB、数据分区 ≥ 20 GB、EFI ≥ 64 MB，而且界面不会发送
> `allow_small_partitions`（旧业务 JSON 里那个逃生口随配置文件一起移除了）。所以真实写盘用的
> VHDX **至少 100 GB**；拿 8 GB 小盘测会在计划阶段就报“分区过小”，不会清盘。
> 只想验证命令链路时用演练模式（`--dry-run`）即可，不需要大盘。

```powershell
python -m app.gui_web.main --serve --port 8765
```

在界面里走四步向导（勾选虚拟盘 → 分区大小 → 选镜像与版本 → 生成计划并确认）。
命令行入口已移除：真实执行的授权来自“界面勾选明白分区会被删除”，
护栏来自写盘阀门：`protectSystemDisk` 决定受保护盘能否入选，提交后服务端仍要过白名单与身份复核。第 4 步的勾选就是授权动作，提交时不再弹第二次确认框。（历史记录里的 `--test-mode` 只允许
虚拟盘，该开关随命令行入口一起移除。）
预期结果（取决于测试镜像）：

- 镜像里**真的有 Windows 目录**（含 `Windows\Boot` 与 `Windows\System32\config\SYSTEM`）：
  六步全绿，`boot` 步骤会报到 `已写入 UEFI 引导……；引导校验通过：bootmgfw.efi / SYSTEM`；
- 镜像**只有引导文件**（为了跑通 `bcdboot` 而用 `C:\Windows\Boot` 捕的合成镜像）：
  前五步成功，**`boot` 判失败**（“系统分区里没有 Windows 系统文件”）。这是设计如此：
  装完能不能开机，以分区里的实际文件为准，不以命令退出码为准。

GUI 真实路径（需要管理员）：

```powershell
python -m app.gui_web.main --serve --settings D:\sisp-test\settings.json
# 然后 POST /api/prepare -> /api/submit -> /api/confirm
```

`/api/confirm` 只收任务 id，确认文本已在旧版本移除：

```json
{"job_ids": ["disk1-xxxx"]}
```

## 已知限制

- 上述 VHD 测试使用的是合成 GHO，未验证真实 Windows 装机的可启动性；
- 未在物理盘上测试，也不应在有数据的盘上测试；
- 协作式取消只能在步骤边界停止；Ghost 还原一旦开始不会被中途打断；
- 运行中强杀进程可能留下盘符/分区中间状态（依赖下次规划避开幽灵盘符）；
- `tools/ui_smoke.mjs` 第 3 步的断言仍按旧的 `select[data-image]`（WIM/ISO 下拉）计数。
  界面换成两个具名槽位按钮（`.vchip`）后该计数恒为 0，所以**第 3 步目前没有自动化覆盖**，
  只能人工看截图；补断言的方式是数 `#wzBody button.vchip` 并断言点击后“下一步”可用。
- 测试 VM（100 GB 测试盘 + 没装 `ghost64.exe`）跑 `node tools/ui_smoke.mjs` 会稳定报 15 条问题
  （「快捷容量 200 之后 D 与 E 没有平分」「点 ➕ 之后额外分区行数为 0」「超过磁盘容量 100 GB」等）。
  用改动前的 `HEAD` 重跑得到**完全相同**的 15 条，属环境所致，不是回归；真实盘（≥100 GB 且 C 默认 ≤ 剩余）与装好 Ghost 的机器上应为 0。

## 安全红线

1. 真实写盘前确认目标是**一次性虚拟盘**或专用测试机磁盘；
2. 真实执行前在界面上核对盘号/型号、勾选「我明白这些分区会被删除」，并确认目标盘不在禁止名单里；
3. 生产环境优先 `--dry-run`（设置里已没有“默认演练”开关）；
4. 不要在含重要数据的物理盘上运行任何真实执行测试；
5. **单元测试里禁止真实盘号**：`tests/` 下的 `disk_number` 一律 ≥ 100（或使用虚构对象），
   真实盘号只能出现在 VM 集成测试脚本里；
6. **不要用"直接赋值"去 mock 实现细节**（`runner._run_diskpart = fake`）：
   Python 不会校验属性是否存在，实现搬家后 mock 会静默失效；
   现在的标准做法是**构造期注入替身**：
   `WindowsDiskRunner(shell=FakeDiskpartShell(...), process=FakeProcess(...))`，
   或直接测阶段 `PartitionPhase(FakeShell())` / `SystemPhase(FakeProcess())`；
   替身与"完美分区表"构造器在 `tests/fakes.py`，夹具在 `tests/conftest.py`
   （`fake_shell` / `fake_process` / `fake_uefi` / `make_runner` / `make_snapshot`）；
7. 改动执行器/分区/引导/镜像相关代码后，**先改对应测试、只跑受影响的单文件**，
   确认没有 `diskpart` 进程，再跑全量；
8. 不要试着把写盘命令“藏”过护栏（`-File` / `-EncodedCommand` / `Start-Process` /
   `iex`）：这些形态要么被按危险拦下，要么本来就需要显式授权。护栏只保证“没授权就不执行”，
   不能当“可以随便试”的理由。

### 护栏自检（四条命令，任何一条不对劲就别跑全量）

```powershell
# 1) 测试环境下危险命令必须被拦（应打印 blocked）
python -c "import os; os.environ['SISP_BLOCK_REAL_DISK']='1'; from app.safety_guard import ensure_command_allowed, RealDiskBlocked;try:
    ensure_command_allowed(['diskpart.exe','/s','x'], allow_real_disk=True)
except RealDiskBlocked:
    print('blocked')"

# 2) 未授权的 runner 必须拦
python -c "from app.application.real_runner import WindowsDiskRunner, _CommandLog; from app.safety_guard import RealDiskBlocked;r=WindowsDiskRunner(diskpart='diskpart.exe');try:
    r._run_diskpart(['select disk 999','clean'], _CommandLog(None))
except RealDiskBlocked:
    print('blocked')"

# 3) “藏起来”的写盘调用也必须拦（应打印 blocked）
python -c "from app.safety_guard import is_dangerous_command as d;cases=[['powershell.exe','-File','x.ps1'],['powershell.exe','-Command','Start-Process diskpart'],['powershell.exe','-Command','Get-Disk | Format-Table']];print(['blocked' if d(c) else 'allowed' for c in cases])"

# 4) 跑测试时确认没有 diskpart 进程（另开一个窗口）
Get-Process diskpart -ErrorAction SilentlyContinue
```
