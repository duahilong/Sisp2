## 2. 专用 VM：只读与 dry-run

### 先把代码/产物送到 VM：优先走 Git

大文件（源码树、`dist/Sisp2.exe`）**不要用 MCP 的文件通道搬**：

- `read` 超过 50 KB 会被截断，写回去就是半个文件；
- 写入会把 LF 转成 CRLF，`git apply` 直接失败（退出码 128），而且补丁里的行尾混着两种；
- 实测能用的兜底只有“分片 base64 + VM 端解码”，又慢又容易传错。

所以默认流程：本机 `git push` → VM 上 `git pull` / `git clone` → 在 VM 里跑测试。
只需要跑产物时才把 `dist/Sisp2.exe` 单独拷过去，并核对 SHA256。

推荐在专用 Windows VM 上验证真实 PowerShell 扫描与 GUI：

```powershell
python -m app.gui_web.main --serve --dry-run --port 8765
```

检查项：
- 磁盘列表、系统盘/启动盘保护、盘符分配、缺镜像/容量不足的阻断；
- `GET /health`、`/api/info`、`/api/disks`、`/api/prepare`；
- `--dry-run`（或 `dryRunByDefault`）会话下，API 传 `dry_run:false` 仍应保持演练；
- 重复 `submit` 返回 `E_SUBMIT`。

## 3. 一次性 VHDX：真实写盘（推荐）

不碰系统盘和物理盘，测完直接 detach/删除。需要管理员权限。

### 3.1 创建并挂载测试盘

```powershell
New-Item -ItemType Directory -Force D:\sisp-test | Out-Null
@'
create vdisk file="D:\sisp-test\sisp-test.vhdx" maximum=8192 type=expandable
select vdisk file="D:\sisp-test\sisp-test.vhdx"
attach vdisk
exit
'@ | Set-Content $env:TEMP\vhd.txt -Encoding ASCII
diskpart /s $env:TEMP\vhd.txt
Get-Disk   # 找到新出现的 "Msft Virtual Disk"（RAW、File Backed Virtual）
```

### 3.2 准备一个合法测试 WIM

真实执行器要求镜像存在且能被 dism 应用。没有 install.wim 时，可以用
`dism /Capture-Image` 从一个小目录生成。若还想验证 `bcdboot`，源目录至少需要：

- `Windows\Boot`（从 `C:\Windows\Boot` 复制）
- `Windows\System32\bootstr.dll`
- `Windows\System32\bcd.dll`
- `Windows\System32\config\BCD-Template`
- `Windows\System32\zh-CN\bootstr.dll.mui`（按系统语言选择 MUI）

```powershell
# 组装 D:\sisp-test\src 后
dism /English /Capture-Image /ImageFile:D:\sisp-test\test.wim `
  /CaptureDir:D:\sisp-test\src /Name:SispTest /Compress:fast
```

> 这个 WIM 只用于验证命令链路，不是可启动的 Windows 镜像；真正验证装机可启动性需要官方 install.wim。

### 3.3 配置与执行

```json
{
  "partition_info": {
    "efi_size_mb": 100,
    "c_size_gb": 3,
    "data_size_gb": "auto",
    "allow_small_partitions": true
  },
  "image_info": { "image_path": "D:\\sisp-test\\test.wim", "image_index": 1 },
  "excluded_disk_names": []
}
```

> `allow_small_partitions` 是**必须**的：后端下限是 C ≥ 60 GB、数据分区 ≥ 20 GB（E ≥ 1 GB），
> 8 GB 这类小盘／单测必须显式放宽，否则计划阶段就报“分区过小”，不会清盘。
> 界面永远不发这个字段，它只给测试与文档用。

```powershell
python -m app.gui_web.main -j D:\sisp-test\config.json --serve --port 8765
```

在界面里走四步向导（勾选虚拟盘 → 分区大小 → 选镜像与版本 → 生成计划并确认）。
命令行入口已移除：真实执行的授权来自“界面勾选 + 输入确认文本”，
护栏来自设置里的 `typeToConfirm` / `protectSystemDisk`。（历史记录里的 `--test-mode` 只允许
虚拟盘，该开关随命令行入口一起移除。）
预期结果（取决于测试镜像）：

- 镜像里**真的有 Windows 目录**（含 `Windows\Boot` 与 `Windows\System32\config\SYSTEM`）：
  六步全绿，verify 会报到 `引导 bootmgfw.efi；系统 SYSTEM`；
- 镜像**只有引导文件**（为了跑通 `bcdboot` 而用 `C:\Windows\Boot` 捕的合成镜像）：
  前五步成功，**verify 判失败**（“系统分区里没有 Windows 系统文件”）。这是设计如此：
  装完能不能开机，以分区里的实际文件为准，不以命令退出码为准。

GUI 真实路径（需要管理员）：

```powershell
python -m app.gui_web.main --serve -j D:\sisp-test\config.json `
  --settings D:\sisp-test\settings.json
# 然后 POST /api/prepare -> /api/submit -> /api/confirm
```

`typeToConfirm=true`（默认）时确认请求要带 `confirm_text`，值为盘号或磁盘型号：

```json

```

### 镜像闸门与 verify 判据（2026-11，源码 + exe 实测）

### 本轮顺带修的两个问题

### P1：授权竞态、危险路径测试与提权（2026-11，exe 实测）

| 用例 | 做法 | 期望 | VM 结果 |
| --- | --- | --- | --- |
| A1 | 真实模式 `prepare`（`test2.wim`） | `executable=true`，盘符齐全 | ✅ |

刷新页面会重开会话并清空隐式授权，不补这一步的话，已排队任务确认时会被

确认文本不对则不授权（A6 覆盖）。

同一轮还补了 17 条危险路径测试：五道闸门逐条分支（dry-run / 白名单 / 弱身份 /
盘消失 / 身份不一致 / 受保护 / 通过）、执行器失败分支（dism 87、bcdboot 2、
verify 拒绝、diskpart 超时，bcdboot 失败仍释放盘符）、设置导出/导入往返与坏文件。

**提权**：早期版本把 GUI exe 声明成 `requireAdministrator`（spec `uac_admin=True`），
双击就弹 UAC；后来发现这与 WebView2 硬冲突——WebView2 的运行时只能以 Medium IL 启动，
提权进程下要把 `msedgewebview2.exe` 降权拉起，而那条路要借 `explorer.exe`，失败时就是
`msedgewebview2 has stopped working` + `Error launching CrashSender.exe`。
现在清单是 `asInvoker`，写盘能力在界面用 UAC 拉起的后端子进程（`--backend`）里；
打包后应能在 exe 里搜到 `asInvoker`、搜不到 `requireAdministrator`（`tests/test_packaging.py`
与 `tests/test_gui_backend.py` 钉住了这两头）。

**A5 顺带暴露并修掉**：镜像路径没归一化，设置里写 `D:/x/test.wim` 时 dism 报退出码 87
（`parameter is incorrect`）——而且发生在清盘之后。现在 `_apply_image_defaults` /
`_merge_payload(win_gho)` 统一 `str(Path(...).expanduser())`，VM 上就是拿正斜杠路径跑通的。

### 只有打包后才暴露的问题（已修）

在源码模式下看不到的差异，靠 exe + 真机才浮出来：

### 这台机器上的两个坑

- **40 GB 的系统副盘不够用**：默认 C=120 GB，`sysDefaultGb` 的下限是 60 GB，
  所以不到 ~81 GB 的盘永远过不了体积校验（第 2 步「下一步」直接禁用）。测整盘安装
  请用 ≥200 GB 的可扩展 VHDX（`create vdisk maximum=204800 type=expandable`，实际占用很小）。
- **合成 WIM 的 `Windows\System32` 为空时，bcdboot 一定失败**
  （`BFSVC Error: BCD strings MUI load failure ... bootstr.dll`）。这是 §3.2 那条
  “源目录至少需要”的清单没抄全时的表现：按清单补上 `Boot`、`System32ootstr.dll`、
  `bcd.dll`、`config\BCD-Template`、`zh-CNootstr.dll.mui` 重新 capture 后，
  `test-full.wim`（67 MB 源，30 MB WIM）跑出六步全绿，ESP 里有 1.5 MB 的
  `EFI\Microsoft\Bootootmgfw.efi`；
- 临时绕法：把设置里的「引导文件目录」`sysBoot` 指向真实 Windows 目录（`C:\Windows`）
  也能让 boot 步通过（当时就是靠它把失败步跑成绿的），但那是兜底路径，不是常规用法。

### 由此修掉的两个产品缺陷

1. `_apply_image_defaults` 只在镜像路径为空时兜底 → 模板里的占位路径
   （`json/win11.example.json` 的 `D:\images\win11.wim`）压住了设置里的 `sysWim`，
   用户在设置页填了真镜像仍然一直看到「镜像文件不存在」。现在无 `-j` 时设置覆盖配置。
2. 预检自己读配置算镜像，绕过了上面那条覆盖规则 → 会话仍然带阻断项。
   `preflight` 改为与运行时同一套优先级（显式 `-j` 才配置优先）。

- 上述 VHD 测试使用的是最小合成 WIM，未验证真实 Windows 装机的可启动性；
- 未在物理盘上测试，也不应在有数据的盘上测试；
- 协作式取消只能在步骤边界停止；取消中的真实 dism 不会被打断；
- 运行中强杀进程可能留下盘符/分区中间状态（依赖下次规划避开幽灵盘符）。

## 安全红线

1. 真实写盘前确认目标是**一次性虚拟盘**或专用测试机磁盘；
2. 真实执行前在界面上核对盘号/型号并输入确认文本，并确认目标盘不在禁止名单里；
3. 生产环境优先 `--dry-run` / `dryRunByDefault`；
4. 不要在含重要数据的物理盘上运行任何真实执行测试；
5. **单元测试里禁止真实盘号**：`tests/` 下的 `disk_number` 一律 ≥ 100（或使用虚构对象），
   真实盘号只能出现在 VM 集成测试脚本里；
6. **不要用"直接赋值"去 mock 实现细节**（`runner._run_diskpart = fake`）：
   Python 不会校验属性是否存在，实现搬家后 mock 会静默失效；
   正确做法是通过构造参数注入（`shell=` / `runner=`），或用 `monkeypatch.setattr`
   让"方法已不存在"立刻报错；
7. 改动执行器/分区/引导/镜像相关代码后，**先改对应测试、只跑受影响的单文件**，
   确认没有 `diskpart` 进程，再跑全量。

### 护栏自检（三条命令，任何一条不对劲就别跑全量）

```powershell

# 3) 跑测试时确认没有 diskpart 进程（另开一个窗口）
```

### 6. 观察与已知限制

### 属预期、不是缺陷

- `boot/report` 出现 `orphan_esp`（warn）：测试镜像是从 `C:\Windows\Boot` 捕的合成 WIM，
  盘上没有 `Windows` 目录，所以「ESP 存在但没找到 Windows」是正确判断；
- ESP/C/D 的 `file_system` 在列表里为 `null`：盘符已释放，`Get-Volume` 读不到卷，
  这是扫描器的既有口径（界面按 GPT 类型显示 EFI 并用紫色区分）；
- 首次运行会在 exe 旁生成 `json/win11.json`（内容 = `win11.example.json` 模板），
  其中镜像是占位路径 `D:\images\win11.wim`；v1.0.1 的行为是**设置优先**，所以填了
  `sysWim` 后会话不再报镜像阻断（本轮 B1 已验证）。

### 测试过程中遇到的问题（环境/脚本，非产品）

1. VM 上 `Invoke-WebRequest` 访问 `http://10.2.0.165:8970` 报「无法连接到远程服务器」，
   而 `Test-NetConnection` 同端口通——系统代理所致；改用 `System.Net.WebClient` 并
   `$wc.Proxy = $null` 后正常。
2. 测试脚本自身两处断言写错（第一轮 14/16）：
   - A3 把 HTML 当 JSON 解析 → 改为 `raw=True` 读取并按字符串断言；
   - A5 误以为 `PUT /api/settings` 回 `{settings:{…}}`，实际回的是扁平设置字典。
   修正后演练 16/16、真实 23/23。

### 本轮未覆盖

- **未签名**：SmartScreen 会提示「未知发布者」，本轮直接运行（未走下载拦截流程）；
- 未验证真实 Windows 装机后的可启动性（用的是合成 WIM）；
- 未测桌面窗口模式（pywebview），本轮全部通过 `--serve` + Edge；
- 未测多盘并发安装、安装中途取消、断网/断电等异常路径；
- 未做长时间稳定性（连续多次安装）与内存/句柄泄漏观察。
