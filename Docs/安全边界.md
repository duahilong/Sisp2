# 安全边界与已知风险

Sisp2 的真实写盘会清空目标盘。以下描述的是当前代码行为，不是风险消除承诺。

## 写盘门禁

`SispService.execute_spec()` 对真实任务要求四道闸门：任务不是 dry-run、服务自身不是 dry-run、盘号在 `allowed_disk_numbers` 中、**执行前重扫一次并复核身份**（有 `UniqueId`/`SerialNumber` 就比标识，没有则比盘号 + 容量 + 型号）、目标盘在执行那一刻仍可选（重新扫描后按 `protectSystemDisk` 重算保护原因：系统盘/启动盘/含系统盘符/离线/只读）。任一不通即 `PermissionError`；身份复核保证「计划阶段可选」不会因为中途换盘/挂载而失效。`WorkflowController` 默认装配 `WindowsDiskRunner`，但服务构造本身不等于用户确认。

确认环节有两道人工闸门，都由设置控制：`confirmBeforeStart` 决定界面是否要求先勾选「已核对目标磁盘」才能提交/确认；`typeToConfirm` 决定 `confirm()` 是否必须收到与盘号或型号匹配的 `confirm_text`（`1`、`disk 1`、`硬盘1`、型号等，忽略大小写与空白）。存在阻断项的计划会先被拒绝，提示里带不可选原因。

计划阶段还有一道**镜像可应用性**门禁：ISO（Ghost 只能还原 GHO）、WIM/ESD/SWM（dism 路线已移除）、后缀不是 GHO/GHS、文件头不是 Ghost 签名（`FE EF`）、找不到 `ghost64.exe`，都会变成计划阻断项并让“开始”置灰。理由很实际：这些情况如果拖到写入阶段才发现，盘已经被 `clean` 了。装机结果也不以“命令退出码 0”为准：`verify` 会检查 EFI 分区里真的有 `bootmgfw.efi`、系统分区里真的有 `Windows\System32\config\SYSTEM`，缺失即判任务失败。

**EFI 临时盘符按“磁盘号 + 分区号”释放，不按字母选卷**：计划阶段分配的字母只保证“当时空闲”，执行期间可能被其它卷（U 盘、重挂载）占用；而 diskpart 的 `select volume <字母>` 是**按字母选卷**的，不确认就 `remove letter` 会摘掉别人的盘符。现在的做法是先定位目标盘上的 ESP（按 GPT 类型 `c12a7328-…` 找分区号，优先复用布局复核时已经拿到的编号），再 `select disk N` + `select partition k` + `remove letter=X`——操作对象是确定的分区，字母被谁占用都不影响。找不到 ESP（盘还没分区/分区表被改过）或查询失败就跳过并写日志。

**为什么不“先按字母查归属”**：ESP 是隐藏卷，实测（Win10 19045）`Get-Partition -DriveLetter E`、`Get-Volume -DriveLetter E`、`Win32_Volume -Filter "DriveLetter='E:'"` 全都查不到它临时分配的字母（只有 `Win32_LogicalDisk` 能看到）。按字母查归属会稳定地“查空 → 跳过释放”，幽灵盘符反而留下来，下一次 `assign letter` 就可能失败。

GUI 的有效模式只由命令行 `--dry-run` 决定（设置里不再有默认演练开关），并且构造时的 dry-run 是硬上限：后续界面或 API 的 `start_session(dry_run=false)`、`prepare(dry_run=false)` 不能关闭它。真实模式的 `prepare()` / `authorize_disks()` / `confirm()` 只会把**本次勾选并确认过的盘**加入服务白名单（`confirm()` 在确认文本校验通过后按任务盘号重新补齐——刷新页面会重开会话并撤掉隐式授权，不补的话已排队任务会因为白名单为空而无法确认）；上一次 `prepare()` 隐式加入且本次未选中的盘会被撤出，新会话也会清空这些隐式授权。因此 GUI 选盘不是独立于该策略的额外白名单来源，使用者必须特别核对盘号与身份。

系统/启动盘、离线盘、只读盘、含系统盘符的盘及型号命中 `excluded_disk_names` 的盘会被标为不可选。保护判断和执行前身份复核不能替代备份、人工核盘或隔离测试。

`protectSystemDisk` 可以从设置里关掉；关掉后系统盘/启动盘会重新变成「可选」，此时剩下的拦截只有白名单、执行前的身份复核和人工确认。请把这看作“拆安全网”，只在隔离测试机或专门的装机环境里使用。（离线盘、只读盘这两种保护不受该开关影响，永远生效。）

同一块盘同时只允许一个未结束任务：重复 `submit` 会被拒绝；`confirm_batch()` 在锁内唯一认领任务，重复确认不会再次启动执行器。这用于防止双击、HTTP 重试或并发调用导致同一块盘被并发清空。

## 测试与非生产环境的写盘护栏（`app/safety_guard.py`）

真实写盘会清盘，所以执行层除了业务闸门，还有一道**与业务无关的运行时护栏**：

```
DiskpartShell / ProcessShell（app/application/shell.py）
BootRepairer / run_powershell
        →  ensure_command_allowed()  →  subprocess
```

判定顺序（任一命中就抛 `RealDiskBlocked`，命令**不会**被交给操作系统）：

1. **实例未授权**：`WindowsDiskRunner(...)`（它会按任务造 `DiskpartShell` / `ProcessShell`）/
   `BootRepairer(...)` / `WindowsDiskRunner(...)` 的 `allow_real_disk` 默认是 `False`，只有生产入口
   `build_real_runner()`、GUI 的 `_boot_repairer()` 与 `_image_probe()` 显式传 `True`；
2. **测试环境**：进程里存在 `PYTEST_CURRENT_TEST`；
3. **环境封锁**：`SISP_BLOCK_REAL_DISK=1`（`tests/conftest.py` 会全局打开）。

**什么算“写”**（只拦写不拦读，否则界面连硬盘列表和镜像索引都拿不到）：

- 外部程序：`diskpart` / `format` / `bcdboot` / `bootrec` / `ghost*` 按**程序名**判定；`dism` 与 `ghost*` 再看参数——
  `dism /Get-WimInfo` 这类 `/Get-*` 只读动词放行，`/Apply-Image`、`/Add-Driver`、
  `/Cleanup-Image` 一律危险；`ghost64 -ver` 这类版本探测放行，`-clone`（还原/打包镜像）与“无参数打开交互界面”一律危险；
- PowerShell 看四件事，任一命中即拦：
  1. 脚本里的**写盘 cmdlet**：`Format-Volume`、`Clear-Disk`、`New-Partition`、
     `Mount-DiskImage` / `Dismount-DiskImage` 等（挂载/卸载改系统状态，也要授权）；
  2. 脚本里的**外部写盘程序调用**：`Start-Process diskpart`、`& 'C:\…\bcdboot.exe'`、
     `; diskpart /s …`——否则 `-Command "Start-Process diskpart …"` 会绕过程序名检查；
  3. **看不到内容的调用**：`-File script.ps1`、`-EncodedCommand`、命令行上的大块 base64，
     以及 `Invoke-Expression` / `iex`（动态执行拼出来的字符串）一律按危险处理；
     不解析内容，也不给“看不出来就放行”的余地；
  4. 以上文本判定前**先按引号感知剥注释**：`Get-Disk # 注释` 剥掉，但
     `-ImagePath 'D:\a#b\x.iso'` 里的 `#` 是路径字符。旧实现按 `#` 硬切，会把引号后面的
     `Clear-Disk` 一起切掉而漏判——这类漏判比误伤更危险，所以剥注释必须识别引号。

只读查询（`Get-Disk`、`Get-Partition`、`Get-Volume`、`dism /Get-*`、`ghost64 -ver`）一律放行；界面扫描走
`app/modules/common/service.run_powershell()`，它也过护栏且默认不带授权。

**已知残余**：变量拼接的调用（`& $cmd`）与 `-File` 指向的脚本内容不做解析；这类“必须真跑才会知道
它想做什么”的写法，靠的是前两道闸（实例未授权 + 测试环境封锁），而不是 cmdlet 文本匹配。

这条护栏的由来是一次真实事故：重构把分区实现搬家后，测试里"直接赋值"的 mock 静默失效，
`pytest` 真的执行了 `diskpart clean`。完整复盘与回归清单见
[《事故报告-2026-11-06-磁盘被格式化》](事故报告-2026-11-06-磁盘被格式化.md)。


## Web 暴露面（高风险）

服务默认监听 `127.0.0.1`。loopback 模式启用 Host 名称校验，允许 `localhost`、`127.0.0.1`、`::1`（含方括号形式）；它用于缓解异常 Host/DNS rebinding 场景，**不是身份认证、授权或 CSRF 防护的等价物**。同源托管且不启用 CORS 也不构成认证。

`--host` 可改监听地址。非 loopback 绑定会关闭 Host 校验，当前没有鉴权；可从网络访问的接口包括任务准备、确认等写盘相关操作。将服务绑定到 `0.0.0.0` 或其他非 loopback 地址应视为高风险，不要在不可信网络暴露。

## 事件与日志

WebApi 事件缓冲最多保留 5000 个事件；旧事件淘汰后游标补发不完整。每条 SSE 连接队列上限为 2000，满时丢弃新事件。SSE 首帧及轮询补发依赖 WebApi 进程内缓冲，不能保证完整补发。重启服务也会丢失该内存缓冲；JobManager 的可选 JSONL 事件落盘不是 WebApi 游标补发来源。

真实执行可记录命令、输出及错误日志（目录取设置中的 `logDir`）；日志可能包含路径、配置和系统信息，须按敏感数据保护。桌面进程另写 `app.log`（RotatingFileHandler，2 MB × 3），启动时按 `logRetentionDays` 清理过期的 `disk-runner-*.log`、`boot-disk*.log` 与 `app.log.*`。窗口位置写在设置文件同目录的 `window.json`（`rememberWindow=false` 时不写也不恢复），不包含业务数据。取消是协作式，运行中的步骤通常先完成；用户已请求取消的任务最终状态记为 cancelled，执行器返回的失败详情仍保留在结果里。

## 预检边界

预检检查管理员状态（dry-run 下不要求）、PowerShell 可用性及系统盘剩余空间，再按界面设置检查：`sysImageA` / `sysImageB` 两个系统槽位里的 GHO 是否存在、后缀是否 `.GHO`/`.GHS`、文件头是不是 Ghost 签名 `FE EF`；填写的外部工具（`extGhost` / `extVentoy` / `ext7z`）是否存在；`sysBoot` / `sysTemp` 的类型与存在性（`sysTemp` 会用完即建）。两个槽位都空着时预检不报镜像问题（没有可检查的对象），真实执行器随后会拒绝缺少镜像路径的任务。这些检查只证明路径与文件头，不证明镜像可引导或工具兼容。

## 验证边界

当前测试主要使用替身扫描器、执行器和注入依赖，覆盖安全分支及命令构造，不应描述为真实 Windows 磁盘端到端验证。不要在含重要数据的物理盘上试运行。
